Redline review: session 2026-10-15

Code and performance review, read-only. Range 083c648..59447c2 on world/space-age (25 commits; tools, contracts, unity/Assets/Suborned, plus the render settings those commits touched). Reviewed on a snapshot of HEAD (git archive 59447c2 into out/review/head) because Splice is editing tools/people and contracts/people in the working tree. Reviewer: Redline (code-performance-reviewer). For Aster.

Summary

The people pipeline is deterministic where it counts: every draw comes from rng(id) (FNV-1a seeded mulberry32), persons, places and units are sorted before output, and no Map, Set or object-key order reaches the people file unsorted. r013 replays OK at HEAD and the people tools hash at HEAD equals r013's. The problems are around the checks, not the draws. M-2 and the Unity layer read whatever out/people file was written last and check only the plan id and version. P-9's "byte-identical twice" compares a file with itself on every real path. Replay compares check rows, which can't see changed people. The Handover's roles are checked only in the first minute of their window. For the whole-district run, the expander has no simulated tier for workers: about 10.7k people would be simulated against a budget of 600, and the name pool runs out (P-8 fails with 3,772 faults). On the Unity side, the A/B harness is sound in its mechanics but two things weaken what the numbers claim: the people layer and its per-frame IMGUI panel can enter the perf scene unrecorded, and the "as-was" baseline runs on the B6 geometry.

High H1. M-2 and the Unity people layer trust whatever out/people file was written last

Where
tools/missions/handover/overlay.ts:26, 39-42 (reads out/people/<plan>.people.json; checks plan.id and plan.version only) · tools/people/cli.ts:20-26 (no --cast = the stand-in, written to the same default path) · tools/people/inputs.ts:30 and contracts/people/people.schema.ts:46 (inputs = cast, life, block, rules; no mission, no plan text, no tools hash; nothing reads inputs) · unity/Assets/Suborned/Editor/World/People/PeopleLayer.cs:32, 68-71 (same default path; only the schema string is checked).
Failure
(a) Anyone runs bun run people without --cast: the stand-in ("a valid cast, not a good one") overwrites the file M-2 and Unity read, and the plan checker's M-2 passes on it. (b) mission.json pins another waitress after the file was made: M-2 passes the stale file while "Inez" is still on the old server (probe 5: mission pins p-cafe-12, Inez is p-cafe-11, M-2 ok). (c) An edited file that is not the expansion of its cast passes M-2, and passes every P-rule when handed to the checker (probe 1). The pinned name moves with the mission (roles.ts), but the mission is not in inputs, so a stale file can't be detected even in principle.
Fix
Promote the accepted cast (r013, with Sky's yes) to contracts/people/civic-block.cast.json, and make bun run people default to it. Write the stand-in to a different path (for example <plan>.standin.people.json). Add mission, plan-text and tools hashes to inputs. M-2 should then either re-expand from the promoted cast (0.1 s at civic-block scale) or fail when inputs differ from the current files, and it should check that each pinned name part sits on the role's pinned id. PeopleLayer refuses a file whose inputs.cast isn't the promoted cast.
Owner
Splice (tools/people, M-2 code) · Waymark (M-2 rule text) · Latch (PeopleLayer check) · Sky (promotion yes, via Aster).

High (district) H2. No simulated tier for workers, and civic-block assumptions: the whole-district run doesn't fit

Where
tools/people/expand.ts:133-161 (every staff slot of every unit becomes a tier: 'simulated' person; HOME_SAMPLE, scope.ts:12, samples only residents) · scope.ts:132-134 (one café per scope: the first diner) · expand.ts:52, 90 (the first tram stop for everyone) · scope.ts:110-115 (seats = the civic block's tables) · contracts/people/cast.schema.ts:46 (pool at most 90 × 110 = 9,900 full names) · people.rules.json:425 (assumes 60 × 80 = 4,800 covers a district).

Medium (verify) M5. FadeReach re-tests every renderer each frame the focus moves

Where
Runtime/FadeReach.cs:85-90 (an O(N) loop over every tagged renderer, skipped only when Same(), an exact float compare, holds) · :134 (cutting[i] ??= Twins(...) allocates arrays, and twin Materials, the first time a renderer is reached) · Runtime/ArchitectureFade.cs:98-105 (runs every LateUpdate).
Failure
In play the focus follows the selected person, so Same never holds and the loop runs every frame over thousands of renderers (1,923 proxy LOD groups alone, plus LOD renderers and the 16 m cells, plus the disabled proxy renderers, which are tagged too). Medium (district) M6. Walk grids cost about 2 GB at district scale

Where
tools/people/walk.ts:52-71 (a memo holding one full Float64Array per source, never freed) · :24-25 (the grid is the bounding box of all places plus 60 m) · :57-59 (heap of tuple arrays).
Failure
Probe on the district extent (plots span 616 × 976 m): the grid builds in 31-59 ms, and Dijkstra takes 45-69 ms per source. At 201,664 cells × 8 B = 1.6 MB per source, about 1,150 sources (1,077 work doors, homes, seats, stops) need about 1.9 GB resident and about a minute of Dijkstra. That memory is a problem on a 16 GB Air with Unity open. Time is fine.
Fix
Use Float32Array. Stop Dijkstra once every target place is settled, or past the longest walk a routine allows. Keep a place × place minutes table and drop the grids. Put the blockers in a bin grid (inBlocker scans every box).

Info I1-I5

  • I1 tools/people/scope.ts:102: kiosk units take plots[0] and areas[0], not the plot of their stop, so kiosk staff carry a wrong work.plot.
  • I2 tools/missions/handover/cast.ts:11-12: the header says P-6 casts without rules. It uses them (check.ts:187).
  • I3 Shaders/CrossGlow.shader:32: no DOTS instancing, so the beams and halos fall back from the GPU Resident Drawer. There are few of them.
  • I4 Combine.cs:38 with FadeTags.Layer: every civic batch is cut into 16 m cells, though only the facade-atlas batches fade, which adds renderers for nothing.
  • I5 contracts/people/cast.schema.ts:37: duplicate positions in a row are allowed and double the slots. P-4 catches it, but the schema could reject it.

What is solid

  • Seeded throughout: rng(id), never Math.random. Shuffles and picks run on ordered arrays, and the output is sorted by id. quota builds slots from the row array, not the Map. Knowledge sets are sorted. The review page is byte-stable (tested).
  • Replay of r013 at HEAD: REPLAY OK. The people tools hash at HEAD (59aa3d61…) equals r013's toolsHash. Each pinned input (life, rules, mission, block, plan) is sha-checked before the rerun.
  • The civic-block scope is cheap: 126 people expand in about 0.1 s, and the checker runs in about 10 ms.
  • Perf harness mechanics: buffers allocated once, wall-clock frame times, rotated variant order with A...A repeats, a busy-machine preflight, the renderer copy under try/finally, and every A/B switch reapplied in full on each Apply. The proxy and SSAO switches demonstrably change the counts.
