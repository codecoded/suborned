Redline review: the C# engine

Commit 5448655 ("Engine: the C# sim, headless, 28 scenarios pass", brief 011 A, Keel). Scope: sim/, tools/sim/, contracts/rules/, briefs/011/keel-engine.md. Read-only. Reviewed on a snapshot of the commit (git archive 5448655 into out/review/engine), because the working tree is shared and other agents are editing it. The adversarial probes are a separate console project (out/review/engine-probes) that references the engine and deliberately does not run with invariant culture. Reviewer: Redline. For Aster.

Summary

Determinism holds for state. The library has no float, double, decimal, DateTime, Random, reflection, threads or unsafe code (grep). Geometry is exact integer arithmetic. The A* heap breaks ties by cell index. Every string comparison is ordinal, and the only sorts use total orders. Under adversarial conditions the checkpoint hashes stay identical across seven cultures and across separate processes (where string hashing is randomised), and all 33 scenarios replay through the serialised order format with identical hashes and logs.

The weak spots are the edges. (1) The loader's "unknown = reject" covers events, conditions, effects, orders and scripts, but nothing else. Any other unknown key is ignored, and typos in lazily read sections surface mid-mission as exceptions thrown out of Step(), or as a stack overflow that kills the process. Bun's schema catches all of these for committed files, but Unity's FromTexts path bypasses bun. (2) A refused approach refunds the price recomputed when it lands, not the price it took, so money is not conserved. (3) A 0-second action never lands. (4) The replay record can't verify itself, the start hash is computed over raw bytes, and the checkpoint hash leaves out the debrief's inputs.

Perf. The 50,000 sim-s per wall-s claim reproduces: 52-84k here. Stepping 600 people along baked paths stays cheap. Routing them at runtime, or calling Preview every frame, does not.

Findings

High E1. "Unknown = reject" stops at the event schema

Where
sim/Suborned.Sim/Rules.cs:129-149: Only() guards only events, lines, outcomes, also, witnesses, conditions and effects. The root, values, cell, security, perception, fit, ladders, memory, traceable and preview are read by path with no key check, as are people.rules and the site (Site.cs:28-53). Lazy reads: Rules.cs:194-202 (ParseFit), :205-212, GameOrders.cs:280 (the reports conditions are built and checked only when evaluated), :186-193 (ladder scales). Recursion: GameOrders.cs:274 (cash-covers calls Quote, and Quote calls FirstOutcome).
Failure
Probe 1 (15 mutations loaded through Engine.FromTexts): 13 are ACCEPTED at load. Unknown keys at the rulebook root, in a value entry, in cell, in people.rules and in the site are silently ignored. Typos in the fit table and the reports conditions load fine, then throw FormatException out of Step() during a scenario (4 scenarios threw), after the order's cash was taken and the operative's busy flag cleared. A ladder scale typo and a knownBy typo load and stay latent. An outcome conditioned on cash-covers loads, then recurses until the stack overflows: exit 134, SIGABRT. In Unity that kills the Editor or the player. The bun side rejects 12 of these 13 (Rulebook strict schema plus checkRulebook). The one it misses is loop-s = 0 (E3). So committed files are safe only as long as every load goes through bun first, and FromTexts (brief 011 D: Unity TextAssets or StreamingAssets) doesn't.
Fix
Compile the rules at load. Add Only() on every object the engine reads, and resolve every number, fit, scale, band and event id into typed fields. Validate where each condition kind may appear: no cash-covers in outcomes or price lines. Make Step() unable to throw on rule content. Until then, Unity loads only texts whose sha256 matches what bun test contracts/rules passed.
Owner
Keel (loader) · Latch (Unity load path).

High E2. Money isn't conserved when a refused approach is refunded

Where
GameOrders.cs:105-107 (Cash -= q.Usd when the order is given) · :117 (LandPersonEvent(..., Quote(ev, p).Usd): the refund is re-quoted at landing) · :155 (if (paid > 0 && !charged) Cash += paid).
Failure
Probe 8: Pay to a Loyal guard (routine known) at Neutral. The card quotes 90,000: base 70,000 plus 20,000 for the wrong approach. 90,000 is taken. During the 50 s, standing reaches Menace; probe 8 sets Standing directly to stand in for three witnessed menace incidents. The approach lands as turn.pay.refused, because Menace refuses a Loyal's Pay, and the re-quote no longer holds the wrong-approach line. Cash goes 100,000 → 80,000, so the cell is 20,000 short for an approach that did nothing. The opposite drift (a Mercenary's Hero overcharge) creates money. §04's purse lesson (Pay versus Help) rides on these numbers.
Fix
Record the amount taken on the order (op.BusyPaid), refund exactly that, and hash it. Separately, decide whether the outcome should use issue-time or land-time standing. The rulebook should say which.
Owner
Keel (Motive for the timing rule).

Medium E3. A 0 s action never lands

Where
GameOrders.cs:48-52 (BusyEnd = Tick + T(seconds)) · Game.cs:163-170 (Step increments Tick, then tests BusyEnd == Tick).
Failure
Probe 2, with values.loop-s set to 0: in S10 the Tech stays busy from tick 283 to the end, the loop never comes on, and the run fails entry-seen-camera. Nothing reports why. A negative duration, or one that overflows (E9), locks the same way. Bun's schema accepts 0.
Fix
Land on BusyEnd <= Tick, or land a 0 s action at once. Bound every duration to 1 s or more at load, in both the C# loader and the zod schema.
Owner
Keel · Motive (rule bounds).

Medium E4. Replay: start hash, order log and checkpoints

Where
Debrief.cs:89, 115 (inputs hash = H(rulebook) ^ 3·H(people) ^ 7·H(site) over raw text, folded into StartHash, which is folded into every checkpoint) · Script.cs:22-27 (a script holds the start, the orders and until; no inputs hash, engine version or expected checkpoints) · cli/Program.cs:52-53 (replayIdentical re-plays in the same process) · Hash.cs:23-51 (what is hashed).
Failure
Probe 7: the same S10 on CRLF inputs plays identically (Success at tick 3,097), but the start hash and the final hash both differ. So a Windows checkout of the PC check can't confirm a Mac replay. A BOM-prefixed rulebook fails to load. Probe 6: flipping GuardReachedCafe leaves the hash unchanged, yet it changes the debrief (the investigation becomes "staged-distraction"). A forged ledger row, a forged debrief line and a rewritten log line also leave it unchanged. The hash covers only the counts of the log, chain and actions, and none of incidents, Ledger, DebriefLines, or the orders and their rejection reasons. The tests compare checkpoints and Result only. What holds: all 33 scenarios round-trip through Script.Write → Parse → Play with identical checkpoints and identical logs (probe 5). The engine's own test does S10 only.
Fix
Hash canonical content, not bytes: normalise CRLF to LF and strip the BOM, or hash the parsed tree. Write a run record holding the inputs hash, the engine version (a hash of the engine source or the assembly MVID), the start hash and the checkpoint list, and make play verify a stored record. Add GuardReachedCafe, incidents, Ledger, DebriefLines and the contents of the chain and actions to Hash.State. Make the replay test compare the full --json report.
Owner
Keel · Suture (baselines on the full report).

Medium (district) E5. G.InCone overflows

Where
Geo.cs:94-98: dot * dot in a long. Facings are raw vectors: Path.Heading (Grid.cs:166-171), Enforcer.Pos - chasePos (Game.cs:345), Back().
Failure
Probe 3: a watcher at 0,0 with 30 m reach, facing (65536, 0), "sees" a point 655 m away, and facing (46341, 0) it sees one 926 m away. When |r|·|f| reaches 2^32, dot² wraps to near 0. On the civic block, segments and distances keep dot² below about 10^16. On a district, path segments of hundreds of metres reach the wrap.
Fix
Normalise a facing to a fixed length (1,024) when it is set, or compare with dot > reach * |f| using Isqrt. Add a checked-arithmetic test build (E9).
Owner
Keel.

Medium (N12) E6. The perf claim, and what N12 multiplies

Claim
"~50,000 sim-s per wall-s": it reproduces. perf 50 gave 54,149, 51,904 and 55,220 on this M5 Max (load average 8.6), and the warmed probe gave 83,572. That's 1.2-1.9 µs a tick, about 1,940 bytes allocated a tick in S10 including run setup, and 0.08 µs and 156 bytes a tick when idle. It measures 4 simulated people, 9 occluders and the 0.5 m civic grid, on .NET 10 RyuJIT with tiered PGO. Unity runs Mono (Editor) or IL2CPP (player), typically 1.5-4× slower on code like this, on the Air.
Where
Grid.cs:65-108 (Route allocates the full grid arrays every call, then string-pulls in O(points² · length/10)) · GameOrders.cs:344-352 (Preview routes on every call) · Rules.cs:170-180 and Game.cs:384 (R.RefI and M() walk JSON nodes and allocate a params array and a substring every call, in per-tick paths) · Hash.cs:32-38 (hashes each person's role, temperament and need strings at every checkpoint).
Measured
Preview: 150 µs and about 500 KB a call (one A* each). Route: 0.08 ms and 474 KB on the block; 61 ms and 20.8 MB on a district-sized open grid. Sees(): 135 ns with 9 occluders, 396 ns over 1,000 (no index). RefI: 64 ns and 72 B; a p: ref: 120 ns and 224 B.
N12 extrapolation
  • Baked paths: stepping 600 people along precomputed paths with a 13 m witness prefilter cost 4 µs a tick in the sketch. With everyone near an operative it's at most about 0.35 ms (600 × 4 × Sees). That's roughly 2-10k sim-s per wall-s headless, and under 1 ms of a 100 ms tick in Unity, so it's fine.
  • Runtime routing: 600 routes cost 48 ms and 284 MB of garbage on the block, and 37 s and 12 GB on a district grid.
  • Preview: one call per frame is 30 MB/s of garbage at 60 fps.
Fix
Before N12:
  • bake routine paths at build time (tools/people already has the walks) and step them;
  • pool the A* buffers with a generation counter;
  • cache Preview's walk per (operative cell, target cell);
  • compile the rules into fields;
  • bin people and occluders on a coarse grid;
  • intern the hashed strings.
The HUD calls Preview on change, not every frame.
Owner
Keel · Latch and Glyph (how the HUD calls Preview).

Low E10. Unity: netstandard2.1, Mono, IL2CPP, stripping

Checked
The Release DLL (146 KB) targets .NETStandard,Version=v2.1 and references only netstandard. The library uses no reflection, dynamic, unsafe code, stackalloc, Span, threads or tasks, and it compiles against netstandard2.1 reference assemblies, so every API it calls exists in Unity's profile. Unity 6 loads .NET Standard 2.1 plug-ins under both API compatibility levels. Managed stripping has nothing reflective to break. A link.xml preserving Suborned.Sim is cheap insurance at High stripping.
Risks
  • (a) Equality of hashes across runtimes (.NET 10 versus Mono versus IL2CPP) is expected, since the arithmetic is all integers and the comparers ordinal, but it is unproven.
  • (b) Run.Eq<T> uses EqualityComparer<T>.Default for enums and Pt?. Modern IL2CPP generates these, but only an IL2CPP player run proves it.
  • (c) Engine.Load keeps a static cache keyed by root (Debrief.cs:91-99). With domain reload off, edits to the rulebook aren't picked up, so use FromTexts.
  • (d) The build embeds the absolute PDB path, so the Studio and the Air produce different DLL bytes. That matters if the DLL hash becomes part of replay identity (E4).
  • (e) Any stack overflow (E1) kills Unity.
Fix
Latch's done-check for 011 D: run Scenarios.All in the Mono Editor and in an IL2CPP macOS player, and compare every final hash with play --json from the CLI. Add ContinuousIntegrationBuild (or PathMap) to the csproj.
Owner
Latch · Keel.

Where
Json.cs:70 (a BOM is not whitespace: probe 7 fails to load), :108-112 (number tokens accept leading zeros), :116-136 (raw control characters are accepted in strings; a \u at the end of input throws ArgumentOutOfRangeException, not FormatException).

Strip a leading BOM, reject leading zeros and control characters, and bounds-check \u.

Info I1-I3

  • I1 GameOrders.cs:448-450: Enter sets Inside, EntryInProgress and the chain before Engage reads cell.enter.s. Under a bad rulebook that read throws, Issue reports "rejected", and the state is half-changed, contrary to "a rejected order changes nothing".
  • I2 Debrief.cs:118-130: Engine.Play runs to each order's tick even when it is past until.
  • I3 Hash.cs:44: PatrolPose is hashed without its presence flag, unlike the other poses.

What is solid

  • D4 holds: no floats anywhere in the library. Isqrt is exact, polygon and segment tests are integer, the heap breaks ties by cell index, and number parsing is invariant.
  • State determinism under adversarial runs: the hashes are identical under tr-TR, sv-SE, ar-SA, fa-IR, hi-IN and de-CH, and across two processes (fingerprint e99ec11b5fd3afdf both times).
  • Replay: all 33 scenarios are identical after a round trip through the serialised order format, logs included. The scenarios never write state directly; everything goes through orders or the hashed start.
  • Orders and scripts reject unknown keys and verbs. Rule refs (v:, p:) are all resolved at load. Events, conditions and effects are strict.
  • The tests pass: 113/113 on the snapshot.

using System.Diagnostics;
using System.Globalization;
using Suborned.Sim;

static class P
{

    static (int pass, int fail, string errors) RunAll(Engine.Inputs i)
    {
        int pass = 0, fail = 0; var errs = new SortedDictionary<string, int>(StringComparer.Ordinal);
        foreach (var s in Scenarios.All)
        {
            try { var r = Scenarios.Run(i, s); if (r.Checks.TrueForAll(c => c.ok)) pass++; else fail++; }
            catch (Exception e) { fail++; var k = e.GetType().Name + ": " + e.Message; errs[k] = errs.TryGetValue(k, out var n) ? n + 1 : 1; }
        }
        return (pass, fail, string.Join(" | ", errs.Select(kv => $"{kv.Value}x {kv.Key}")));
    }
