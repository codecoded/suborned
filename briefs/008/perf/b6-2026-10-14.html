008 B6: the glow fix, the A/B harness and two A/B runs on the Air

Latch, 2026-10-14. MacBook Air 15-inch M4 (Mac16,13), Unity 6000.6.2f1, development player, 1920 × 1080 fullscreen window, world only (no people, vehicles or sim). Export 9b2b451d, scene fingerprint 80fdd304, held fixed for every run. Answers Redline's out/review/008-b6-perf.html (item 0, M1–M8, fixes 1–3). Labels: valid contaminated, usable as a ratio invalid.

In short. The player-only glow with black pixels is fixed at its cause: the player's vertex compression gave kit meshes and procedural batch meshes the same 32-byte stride with different layouts; on Metal, drawn in one SRP batch in the depth-normals prepass, that gave NaN normals, which SSAO and bloom spread. VertexChannelCompressionMask 4054 → 0: NaN pixels at home 27,390 → 0, and 0 at every stop of every run since. No Stop NaNs; the harness counts NaN pixels at every stop as the guard.
No A/B number here is clean. The best run (ab-1) overlapped Splice's test suite (one core of ten) and is usable as within-run ratios only; the second run (r2) lost focus throughout, ran half its segments beside other heavy processes and had its capped window throttled: invalid. The clean reference run, the capped pass and the fixes 1+3 comparison are still owed (section 6).

1. The glow and black pixels

The NaN probe renders the play camera without post-processing into a float target and counts non-finite pixels. At home, as built: 27,390. Switches that removed them: SSAO off, SRP Batcher off, environment reflections off, specular off; the procedural bakelite batch off left 302. Shadows, the fade, probes, point lights, the clear coat and the opaque and depth textures changed nothing. A diagnosis player per compression mask (nan/vc*.txt):

0 (the fix)full precision, as in the Editor–0

The procedural batch meshes are readable, so never compressed: P32×3, N32×3, UV32×2, also 32 bytes. Every mask that moves the kit stride off 32 clears the NaNs, so the cause is two layouts behind one stride in the same batch, a Unity/Metal player bug (candidate for a Unity report; the Editor never compresses). With mask 0 the player's layouts equal the Editor's. The fix is unity/ProjectSettings/ProjectSettings.asset, one line. Cost: kit vertex buffers stay full precision (memory, not frame time, at this scale).

Bigger than fixes 1–3: the fade. Fade off halves the heaviest stop (13.1 → 6.6 ms) and north-edge (9.8 → 5.2), −31% at the parade. The fade is gameplay (the cutaway), so it stays, but its cost is likely the discard variant on every architecture material: on Apple's tile GPUs a shader that can discard loses hidden-surface removal, so the whole screen pays overdraw, not only the faded zone. Next step (Latch, Redline item 9): measure a fade whose discard variant is set only on renderers inside the fade reach.
