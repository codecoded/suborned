P2 · Kerb-cut finish not closed — HOLD on kerb finish, not on the surface checkpoint. Full-size curve-north and curve-south after stills, plus raw motion frames 0/18/35, show:

  • Detached dark vertical fins (about 0.1–0.15 m) stand on the bed at kerb-cut points: ≥3 in curve-north, ≥4 in curve-south.
  • They are identical in the tram-settled capture and hidden inside the continuous kerb in the baseline. They are most likely kerb block-joint faces that survived the earlier kerb clip: vertical, so zero XZ area, so invisible to the v3 audit and to the cap logic.
  • The diagonal kerb end in curve-south is only partly capped: a pointed top overhang, a thin hanging blade and a dark slot under the cap remain.
  • Cap faces show vertical joint-like streaks that don't match the adjacent granite.

The 29 cap areas themselves are small (0.0015–0.075 m²); there's no runaway hull. Owner: Latch, in SwapNetwork CrossGround kerb clip and SwapTramKerbCaps.cs. P2 · Introduced memory/build cost; gate before any player build (no compression proposed).

  • Measured from the saved assets: 18.6M vertex records for 6.3M triangles (2.96 per triangle, against the source template's 3,918 / 3,098 = 1.26) and only 3.35M distinct positions.
  • Stride is 56 B, so about 1.04 GB of vertex data. m_IsReadable: 1 on every new mesh (the source importer is non-readable), so a CPU copy is likely retained too.
  • 1,584 unique meshes replace one shared template. 2.0 GB on disk (TramCorrected) plus 1.9 GB (TramSettled).
  • Cause: SwapMesh.Write.Poly gives every polygon fresh vertices, and the per-triangle tangent pass splits corners further.
  • The normal OldTownSwap.Build path runs this by default (SwapNetwork.Rails → SwapTramRender.Apply) and saves through DecoKitStage.Save, so the meshes would be embedded in OldTown.unity. That path has not been run since the change (OldTown.unity dated 15:27).

Runtime frame time is unmeasured. Missing gates: memory/scene-size budget and a fresh normal build. The remedy choice (e.g. lossless restoration of vertex sharing or the readable flag) is Aster/Sky's.

P3 · Tangent convention. Output tangents are per-triangle UV derivatives; the source importer uses tangentImportMode: 3 (MikkTSpace). The attribute proof checks the writer's own convention, so it's circular, and the "source fails 6,776" figure reflects the convention difference, not source defects. The materials use _DETAIL_MULX2 detail normals, so tangents are shaded, but any visible effect at play zoom is negligible. Accept for this checkpoint; record it as a deliberate convention change.

P3 · Proof scope. Bed coverage queries take the highest containing face with no height check, and the tiles have 9,779 m² of down-facing area, so a top-only hole would pass. Rail queries are height-checked (≤10 µm against the source profile) and the seam decode above covers the seams. The frame probe uses Derivatives, not the BasisOf path the writer actually uses, and covers 8 synthetic configurations.

P3 · Renderer replacement. Material, layer, tag and serialized renderer settings are copied. Static flags are not: the prefab sets 87, the new objects have 0. No current effect (static batching off, no occlusion data, no baked GI), but it would matter on future bakes. Property blocks are not serialized, so "copied" has no persistent meaning. The SwapTramMeshRead cache is never cleared (an editor-session leak only).
