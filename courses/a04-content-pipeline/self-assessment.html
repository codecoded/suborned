Self-assessment · A04 content pipeline (run r008)

Submitted run: runs/levels/harbour-district/r008/, ACCEPTED in 3 rounds. It ran on GDD v0.15.0, retrieval chunker v2 and the Oct 9 civic block (café 22 × 11.3 × 34.8 m, rule C-0). Every number below comes from a committed record, or is marked as not reproducible from this commit.

What the pipeline does well

  • Game-specific and replayable. The outputs are edits to the district plan that the game's graybox is derived from. They are judged by the same plan checker that gates every plan. bun run verify replays all ten runs offline in 1–2.5 minutes, with no Docker or model. That includes the derived timetable, and the drift is labelled by cause.
  • Models decide; code computes and checks. Datum chooses lines, Vantage places stops, and Pulse chooses speeds, dwells, headways and routes. Code derives every run time and journey total, and checks citations, walk access and whether hand-offs were answered. In r008 there were 0 citation faults and 0 timetable faults.
  • Owners coordinate through the loop. In r008, Vantage moved Skyport for spacing (round 1) and placed T2's seven stops (round 3), answering Datum's asks done: true in the same round. Keel checked that the answers held. The one ask Vantage answered done: false became a fault for Vantage. Two of the four done: true answers repeat the Skyport ask, which was already met (see weaknesses). Faults went to the owner who can fix them: Keel sent the reach failure to Datum (a line problem), and the line-end failure in round 2 also went to Datum.
  • The GDD rules reach the agents by retrieval, not by prompt. The briefs no longer state the boarding rule. In r008 the chunk §02 LOOP + RESOURCES › travel reached Pulse at rank 4 and Keel at rank 8. The queries were unchanged across rounds, so this is one result, not three. The natural question alone ranks it 1st, and Keel judged the timetable against it ("time only, no fare").
