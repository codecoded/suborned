Start here · human and agent reviewers

Verify the submission on your machine.

From the repository root, with Bun 1.4+ and the .NET 10 SDK:

bun install --frozen-lockfile
bun run goals:verify

Allow ten minutes. No model, database, Docker or Unity is required. Initial package restore may need network access.

Your result: the command prints ASSIGNMENT 5 OFFLINE VERIFICATION PASSED or FAILED, then the path to your newly generated HTML report:

out/goals/submission/<your-check-timestamp>/index.html

Open that printed path for your six check results, execution time, JSON evidence and logs. A successful verification reconstructs the original failing tests and confirms that the recorded patch fixes them; it does not generate a new feature.

Optional · new model execution

Run the agent on another goal.

Follow the live setup and approval instructions. This uses retrieval services and your authenticated model, and can write simulation code.

Your result: terminal output identifies the new run and its report path:

runs/goals/<your-run-id>/index.html

That report shows this run's identity, scope, status, priorities and next actions. It can finish COMPLETE, INCOMPLETE or ERROR. An early startup failure may have only JSON evidence; the terminal reports this explicitly.

The same completed goal can correctly produce zero new work. Use a broader or different goal to discover the next gaps.

What the submission demonstrates

Priority scoring · GDD/code gap detection · automatic code writing · verification and rescan after each write. The archived report maps each requirement to evidence; the README explains reproduction, retained runs, budgets and limitations.

This guide contains no live status indicator. Use the timestamped report printed by your command for your execution's outcome.
