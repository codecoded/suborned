## What the brief actually asks

The assignment does not say every game asset must be generated by one pipeline, nor does it explicitly demand newly purchased model calls. It asks for video showing the pipeline running and generating output assets/data, a traceable connection to content in the playable build, automatic engine integration, and costs from the actual generation run. A focused content pipeline can satisfy that scope if demonstrated properly.

## Why this walkthrough is weak on its own

- It is an annotated presentation assembled after an offline exporter run. It is not a screen recording of the AI generation process or the engine integration executing.
- It shows integration source code and a prior game capture, rather than one recorded execution carrying output into the engine and showing the result there.
- Only 32 grid states are reproduced automatically. Four separately finished downed states are documented exceptions; the complete 36-state chain is not reproducible by that exporter alone.
- Its $1.15560 cost is for the historical portrait campaign. It must not be presented as the total cost of The Suborned or a new end-to-end run.
- Reducing repair-sheet size halved the recorded cost per request, but also changed output scope. This is a useful production optimisation, not a controlled comparison of equal workloads.

## Recommended primary submission

Lead with **GDD and people rules → RAG → Pulse cast generation → deterministic checks and Keel critique → promoted cast → deterministic people/routine expansion → simulation export → Unity/player → relationships and routines affecting the Handover**. Introduce the wider world/asset/build architecture briefly, then follow this one concrete production path. Keep world/DecoKit as the visual companion and portraits as optional supporting evidence.

The recording should retain the command, inputs/seed, prompts and model responses (or clearly identify archived responses), checks, generated filenames/hashes, import output and the same content functioning in Unity/the player. Choose and verify a path already used by the game before recording; do not substitute an unadopted experiment or Assignment 6 proposal. If model output is replayed, label it as replay and keep the original run receipts. Any new live model call needs explicit opt-in, a recorded approver and a bounded budget under repo policy.

The original r016 calls and retries, highest-cost critic call and the shared framework's checks-before-critic change are now calculated in evidence/people.json and the one-page audit. The recorded USD values are subscription usage valuations, not additional API payments. The video keeps manual approval, historical generation and downstream projection differences explicit.

The playable-link gate remains independent: a compatible stranger must reach play within 120 seconds. A working itch.io page, existing screenshots and local build proofs do not establish that timing.
