# The Suborned

> **Marking or reviewing Assignment 4?** Read `AGENTS.md` and start at `courses/a04-content-pipeline/README.md` → "For markers". You are reviewing, not building. Don't edit files, commit, or start the crew. Everything below is for the development crew.

Lean game repo: GDD → crew → plan → visible world. It grows only when a task needs something; the old monorepo (`~/Projects/the-suborned`) is reference, brought over piece by piece.

## Layout
- `GDD/`: current version only. Agent GDD (`.md`; agents load §01 + their own §14) and human GDD (`.html`, wins on conflict; ~2 MB, never load it whole). History: `~/Projects/the-suborned/GDD`.
- `.claude/agents/`: the crew (17), named by job, generated by `bun run crew` from the agent GDD. Edit the GDD, never a card.
- `contracts/world/`: `harbour-district.plan.json` (`suborned.plan/1`, source of truth for the city) · `civic-block.json` (`suborned.block/4`: the civic block at its Oct 9 city scale, café 22 × 11.3 × 34.8 m and the Records Office, with their entrances, structures, street furniture and kerb bays named by place; written by `bun run block` from the Oct 9 sources with sha256; never hand-edit or copy in an older block; checker rule C-0 fails if its scale changes) · `civic-block.adjust.json` (explicit adjustments, each with a reason) · `world.schema.ts` + `harbour-district.world.example.json` (the export contract, `suborned.world/2`) · `kit.json` + `kit.schema.ts` (DecoKit catalogue: per-piece status candidate/adopted/rejected, sha256, source paths) · `harbour-district.life.json` + `life.schema.ts` (city-life rules, brief 005). The world holds buildings, structures, street furniture and bays only; no destinations, routes or cast.
- `contracts/missions/`: one folder per mission, kept out of the world. `handover/mission.json` = the Handover destinations, crew and routes, moved unchanged out of the world (input to brief 003). Its rules (C-3, M-1, mission walk origins) live in `tools/missions/handover/` as an overlay on the checker: `bun tools/plan/cli.ts --overlay tools/missions/handover/overlay.ts`. Recorded runs replay through the same overlay from their pinned block.
- `contracts/style/`: style contract (machine copy of GDD §15).
- `tools/plan/`: plan checker + CAD sheet. `bun run plan` exits 1 on any failed rule; sheet → `out/plan/`.
- `tools/world/`: world generator + export (`bun run world` → `out/world/harbour-district.world.json`): masses, frontages, levels and connectors, megastructures, street furniture, kit refs; deterministic, seeded by id; exits 1 unless the plan passes.
- `tools/kit/`: `bun run kit`, the kit catalogue and the hash-checked copy of adopted pieces into `unity/Assets/Suborned/Kit/` (git-ignored). `tools/decokit/`: the Blender DecoKit generator (`bun run decokit` → `out/decokit/`).
- `tools/levels/`: the A04 transit pipeline (`bun run levels transit`, `levels:replay`); runs recorded in `runs/levels/`. The submitted copy is the `assignment-04` branch: never change that branch.
- `tools/crew/`: crew card generator.
- `tools/rag/`: build-time generation core (ported from Assignment 4). Corpus = agent GDD by §, human GDD by heading, plans by part → SurrealDB (HNSW + BM25, RRF) via `compose.yaml` + `services/embeddings`. `runAgent` runs a crew member tool-less (card body as system prompt, only StructuredOutput) and saves card, retrieval, prompt, schema, transcript and output per call. `bun run up`, `ingest`, `retrieve`. Model calls are opt-in, never in tests.
- `unity/`: Unity 6000.6.2f1 URP project. Unity MCP via `.mcp.json`. Only Latch edits scenes. `Assets/Scenes/HarbourDistrict.unity` is built from the world export by `HarbourWorldBuilder` (`Assets/Suborned/Editor/World/`) and git-ignored; never edit it by hand.
- `briefs/`: objectives Aster hands out (objective · owner · done-check · evidence · next owner).
- `out/`: generated, git-ignored. Evidence that must ship goes in a committed folder, never only in out/.

## Run the crew
`claude --agent lead-producer` (from this folder): the lead (Aster in the GDD) spawns crew by job name (`world-planner`, `unity-engineer`, `tools-engineer`, …). Every card carries the GDD name → agent roster; the GDD and briefs use the names. Any session here can also spawn a crew member directly with the Agent tool.

## Rules
- No commits or deploys unless Sky asks.
- Crew agents share one working tree: never `git stash`, `checkout`, `reset` or `clean`. To compare with the last commit, use `git diff` or `git show HEAD:<path>`.
- Design changes are discussed with Sky before the GDD is edited; a GDD change is a new version, then `bun run crew`.
- The plan is the source; the sheet and the Unity graybox are derived from it. Edit the plan, never what it generates.
- Agents never drive the browser pane. Verify with the plan checker, `bun run typecheck`, Unity compile and console, screenshots.
- bun · rg / ast-grep · reports as self-contained `.html` · scratch output under `out/`.
